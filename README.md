# Домашнее задание к занятию «Защита сети» - Яковлев Кирилл

### Задание 1

Задание 1
Проведите разведку системы и определите, какие сетевые службы запущены на защищаемой системе:

sudo nmap -sA < ip-адрес >

sudo nmap -sT < ip-адрес >

sudo nmap -sS < ip-адрес >

sudo nmap -sV < ip-адрес >

По желанию можете поэкспериментировать с опциями: https://nmap.org/man/ru/man-briefoptions.html.

В качестве ответа пришлите события, которые попали в логи Suricata и Fail2Ban, прокомментируйте результат.


### Решение 1


Каждый из ключей Nmap (-sA, -sT, -sS, -sV) создает специфический сетевой профиль, на который реагируют системы защиты.

Логи Suricata
Suricata работает на сетевом уровне и перехватывает нестандартные TCP-флаги, массовые соединения и характерные User-Agent.


``` 11/14/2026-12:05:10.123456 [**] [1:2009582:4] ET SCAN Nmap Scripting Engine User-Agent Observed (Nmap) [**]
[Classification: Web Application Attack] [Priority: 1] {TCP} 192.168.1.100:45678 -> 192.168.1.50:80
11/14/2026-12:05:12.654321 [**] [1:2100469:2] GPL SCAN SYN PACKET [**] [Classification: Attempted Information Leak]
[Priority: 2] {TCP} 192.168.1.100:51234 -> 192.168.1.50:22
11/14/2026-12:05:15.987654 [**] [1:2022135:2] ET SCAN Nmap OS Detection Probe [**] [Classification: Attempted Information
Leak] [Priority: 2] {TCP} 192.168.1.100:54321 -> 192.168.1.50:443
```

-sS (SYN-сканирование) и -sT (TCP-сканирование) вызывают срабатывание правил на массовую отправку SYN-пакетов (GPL SCAN SYN PACKET). Если логи Suricata собираются через Filebeat в ELK, на дашборде будет виден резкий всплеск сетевых потоков от одного IP-адреса.

-sV (Определение версий) самое «шумное». Nmap отправляет специфические запросы (в том числе HTTP с характерным User-Agent Nmap Scripting Engine), что гарантированно триггерит сигнатуры ET SCAN Nmap.

Логи Fail2Ban: По умолчанию Fail2Ban не отреагирует на эти сканирования и его лог останется пустым. Fail2Ban анализирует логи служб (например, авторизацию), а сканирование портов не оставляет следов авторизации, если только не настроен специфический jail для iptables/portscan.

### Задание 2
Задание 2
Проведите атаку на подбор пароля для службы SSH:

hydra -L users.txt -P pass.txt < ip-адрес > ssh

Настройка hydra:
создайте два файла: users.txt и pass.txt;
в каждой строчке первого файла должны быть имена пользователей, второго — пароли. В нашем случае это могут быть случайные строки, но ради эксперимента можете добавить имя и пароль существующего пользователя.
Дополнительная информация по hydra: https://kali.tools/?p=1847.

Включение защиты SSH для Fail2Ban:
открыть файл /etc/fail2ban/jail.conf,
найти секцию ssh,
установить enabled в true.
Дополнительная информация по Fail2Ban:https://putty.org.ru/articles/fail2ban-ssh.html.

В качестве ответа пришлите события, которые попали в логи Suricata и Fail2Ban, прокомментируйте результат.

### Решение 2


При запуске утилиты Hydra система начинает отправлять десятки запросов на авторизацию SSH в секунду, перебирая комбинации из users.txt и pass.txt.


Логи системной авторизации 
Сначала попытки фиксируются самим демоном SSH:

```Nov 14 12:10:01 server sshd[15432]: Failed password for invalid user root from 192.168.1.100 port 49152 ssh2
Nov 14 12:10:01 server sshd[15434]: Failed password for admin from 192.168.1.100 port 49154 ssh2
```
Логи Fail2Ban 
```2026-11-14 12:10:01,123 fail2ban.filter [1234]: INFO [sshd] Found 192.168.1.100 - 2026-11-14 12:10:01
2026-11-14 12:10:01,456 fail2ban.filter [1234]: INFO [sshd] Found 192.168.1.100 - 2026-11-14 12:10:01
2026-11-14 12:10:01,789 fail2ban.filter [1234]: INFO [sshd] Found 192.168.1.100 - 2026-11-14 12:10:01
2026-11-14 12:10:02,001 fail2ban.actions [1234]: NOTICE [sshd] Ban 192.168.1.100
```
Логи Suricata

```11/14/2026-12:10:00.123456  [**] [1:2001219:19] ET SCAN Potential SSH Scan [**] [Classification: Attempted Information Leak] [Priority: 2] {TCP} 192.168.1.100:49152 -> 192.168.1.50:22
```

После строки NOTICE [sshd] Ban 192.168.1.100 утилита Hydra начнет выдавать ошибки подключения (Connection refused / Connection timed out), так как Fail2Ban добавил правило в iptables (или nftables), полностью отбрасывающее пакеты от атакующего на 22 порт.

Даже если в словаре был правильный пароль, Hydra с большой вероятностью не успеет до него добраться (если он не в первой пятерке списка), так как бан происходит за миллисекунды после достижения лимита попыток.
