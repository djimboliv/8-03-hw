### Решение 1

При базовом сканировании Nmap (например, с ключами -sV для определения версий) на Metasploitable 2 обнаруживается большое количество открытых портов. Вот основные разрешенные сетевые службы:

FTP: порт 21 (vsftpd 2.3.4) и порт 2121 (ProFTPD 1.3.1)

SSH: порт 22 (OpenSSH 4.7p1 Debian)

Telnet: порт 23 (Linux telnetd)

SMTP: порт 25 (Postfix smtpd)

DNS: порт 53 (ISC BIND 9.4.2)

HTTP: порт 80 (Apache httpd 2.2.8) и порт 8180 (Apache Tomcat)

SMB / NetBIOS: порты 139 и 445 (Samba smbd 3.0.20-Debian)

Remote Shell / rlogin: порты 512, 513, 514

Bindshell (бэкдор): порт 1524 (Metasploitable root shell)

Базы данных: порт 3306 (MySQL 5.0.51a) и порт 5432 (PostgreSQL 8.3.0)

VNC: порт 5900 (VNC protocol 3.3)

IRC: порт 6667 (UnrealIRCd 3.2.8.1)

Исходя из найденных версий служб, на сайте Exploit-DB можно найти множество эксплойтов. Вот 3 классические уязвимости для данной машины:

vsftpd 2.3.4 - Backdoor Command Execution (Удаленное выполнение команд)

Описание: Версия vsftpd 2.3.4 некоторое время содержала вредоносный бэкдор в официальном архиве. Если при логине ввести смайлик :) в имени пользователя, демон открывает root-шелл на порту 6200.


UnrealIRCd 3.2.8.1 - Backdoor Command Execution (Внедренный бэкдор)

Описание: Как и в случае с vsftpd, архив с этой версией IRC-сервера был скомпрометирован. Злоумышленник может отправить команду, начинающуюся с букв AB, для удаленного выполнения системных команд с правами пользователя службы.


Samba 3.0.20 - 'Username map script' Command Execution

Описание: Уязвимость (CVE-2007-2447) позволяет выполнить произвольные команды через внедрение шелл-кода при использовании опции конфигурации «username map script». Эксплуатируется без предварительной аутентификации.

### Задание 2
Проведите сканирование Metasploitable в режимах SYN, FIN, Xmas, UDP.

Ответьте на следующие вопросы:

Чем отличаются эти режимы сканирования с точки зрения сетевого трафика?

Приведите ответ в свободной форме.

### Решение 2
Если вы запишете трафик этих типов сканирования в Wireshark, вы увидите четкие различия в том, как Nmap взаимодействует с TCP/IP стеком операционной системы.

Чем отличаются эти режимы сканирования с точки зрения сетевого трафика?

SYN-сканирование (-sS): Это так называемое «полуоткрытое» (Half-open) сканирование. Nmap отправляет TCP-пакет с установленным флагом SYN, инициируя стандартное трехэтапное рукопожатие. Однако, когда сервер отвечает, Nmap не завершает соединение, а обрывает его.

FIN-сканирование (-sF): Относится к категории "stealth" (скрытного) сканирования. Nmap отправляет пакет только с флагом FIN (который обычно означает завершение существующего соединения). Это нарушает логику TCP, так как соединения не существует.

Xmas-сканирование (-sX): Называется «рождественской елкой», потому что пакет «светится, как елка». Nmap устанавливает в пакете сразу три флага: FIN, PSH и URG. Как и FIN, это аномальный пакет, который служит для обхода простых пакетных фильтров без состояния (stateless firewalls).

UDP-сканирование (-sU): В отличие от трех предыдущих, здесь проверяется протокол UDP. UDP работает без установки соединения (connectionless). Nmap просто посылает пустой UDP-датаграмму (или датаграмму со специфичной для службы полезной нагрузкой) на целевой порт.

ОС Linux (на которой базируется Metasploitable) строго соблюдает стандарты RFC 793, поэтому ответы сервера будут следующими:

При SYN-сканировании:

Открытый порт: Сервер ответит пакетом SYN, ACK. Nmap зафиксирует порт как открытый и сразу пошлет RST, чтобы разорвать соединение.

Закрытый порт: Сервер ответит пакетом RST, ACK.

При FIN-сканировании:

Открытый порт: Согласно RFC, открытый порт должен проигнорировать такой аномальный пакет. Сервер не отправляет ничего. Nmap по таймауту помечает порт как open|filtered.

Закрытый порт: Сервер ответит пакетом RST.

При Xmas-сканировании:

Ответы сервера абсолютно идентичны ответам при FIN-сканировании (открытые молчат, закрытые шлют RST).

При UDP-сканировании:

Открытый порт: Часто ответа нет вообще (в Wireshark будет только исходящий запрос), и Nmap помечает порт как open|filtered. Если Nmap использует специфичный payload, служба может вернуть UDP-ответ (тогда статус open).

Закрытый порт: Сервер (точнее, его сетевой стек) возвращает ICMP-сообщение об ошибке: Destination Unreachable (Port Unreachable) (Тип 3, Код 3). Это главный индикатор того, что UDP-порт закрыт.
